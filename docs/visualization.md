# Визуализация

Карта пространства решений: все допустимые размещения `y` рисуются точками на плоскости, а поверх — путь одного запуска VND со всеми просмотренными соседями.

## Установка

Пакет `vnd` по-прежнему работает только на стандартной библиотеке; зависимости нужны лишь для `viz/`:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r viz/requirements.txt   # numpy, matplotlib, umap-learn
```

## Запуск

```bash
.venv/bin/python -m viz.landscape --p 5 --seed 2
```

Результат: `viz/output/landscape_{датасет}_p{p}_seed{seed}.png`.

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `--dataset` | `datasets/20_20_15.txt` | входной файл |
| `--n`, `--m` | `20`, `20` | размеры задачи |
| `--V` | `47000` | порог |
| `--p` | `15` | количество открываемых предприятий |
| `--seed` | `1` | сид случайного стартового решения — разные сиды дают разные пути |
| `--umap-seed` | `42` | сид проекции; от него зависит расположение точек, но не путь |
| `--out` | см. выше | свой путь к PNG |

Первый запуск для пары (датасет, `p`) строит проекцию около минуты, затем она берётся из `viz/cache/` и перерисовка занимает секунды. Чтобы перестроить проекцию — удалить соответствующий `.npy` из кэша.

## Как это устроено

1. Перебираются **все** C(n, p) размещений (для `20_20_15`: C(20,5) = C(20,15) = 15 504) и для каждого считается `V − f`. Подходит только для небольших `n`: при `n = 100` пространство астрономическое.
2. Решения проецируются на плоскость методом UMAP по **расстоянию Хэмминга** — близкие по составу открытых предприятий размещения стремятся оказаться рядом.
3. `solve()` запускается с `tracer=Tracer()` (`vnd/trace.py`): записывается каждое вычисленное соседнее решение и каждый принятый переход. Без `tracer` алгоритм работает как раньше.

## Как читать картинку

| Элемент | Что означает |
|---|---|
| точки, зелёная шкала | все решения; цвет — значение `V − f` (темнее — лучше) |
| белый кружок | стартовое решение |
| толстая красная линия | принятый шаг локального спуска (1-swap) |
| синий пунктир | принятый прыжок `improve` (2-swap) |
| тонкие красные линии | просмотренные, но отвергнутые 1-swap соседи |
| тонкие синие линии | просмотренные 2-swap соседи; «веер» из точки — это полный просмотр окрестности 2-swap |
| красная звезда | решение, на котором VND остановился |
| жёлтая звезда | глобальный оптимум (известен благодаря полному перебору) |

Что можно увидеть:

- **Совпали ли звёзды.** Если красная и жёлтая звёзды в одной точке — VND нашёл глобальный оптимум. Если нет — застрял в локальном оптимуме, и видно, насколько далеко от него лучшее решение.
- **Роль 2-swap.** Синий пунктир показывает, где локальный спуск упёрся в локальный оптимум и окрестность 2-swap вывела его дальше. Количество капилляров — это фактическая цена поиска: сколько раз вычислялись `follower` + `leader`.
- **Сложность ландшафта зависит от `p`.** На `20_20_15` при `p=15` все случайные старты доходят до глобального оптимума одним локальным спуском, 2-swap не срабатывает. При `p=5` (пространство того же размера) 2-swap срабатывает в большинстве запусков, а часть запусков застревает. Примеры: `--p 5 --seed 2` (4 прыжка 2-swap, глобальный оптимум) и `--p 5 --seed 5` (локальный оптимум 37 044 вместо 37 384).

## Ограничения интерпретации

- **Расстояния на карте приблизительные.** У каждого решения `p·(n−p)` соседей по 1-swap (75 при `n=20, p=5`), а любые два решения отличаются не более чем на `min(p, n−p)` обменов. На плоскости такую структуру точно не уложить, поэтому даже один шаг 1-swap иногда пересекает полкарты.
- **Нет гладкого «рельефа».** Проекция строится только по составу решений, без учёта `V − f`, поэтому соседние точки могут сильно отличаться по цвету. Это честное свойство пространства, а не ошибка рисования.
- **Расположение точек условно.** Другой `--umap-seed` даёт другую, но равноправную карту; оси не имеют смысла.
- **Режим `--simplified` на путь не влияет.** `leader` и `leader_simplified` возвращают одно и то же `V − f`, а поиск сравнивает только его, поэтому при одинаковом сиде пути совпадают.
