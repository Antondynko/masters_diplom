# masters_diplom

Исследовательский код магистерской диссертации: иерархическая (bilevel) задача
размещения предприятий с нахождением локального оптимума радиуса пороговой
устойчивости через локальный спуск и окрестности 1-swap / 2-swap.

Python 3.13, только стандартная библиотека (numpy не используется).

## Быстрый старт

Требования: Python 3.10+. Сторонних пакетов нет.

```bash
# активировать venv, если используется
# python -m venv .venv
# .venv\Scripts\activate

# текущий датасет: 20_20_15.txt (заменён вручную в import_from_file.py)
python VND.py
```

На stdout выводятся:

- стартовое размещение `y` и матрица радиусов устойчивости;
- результат `Local_Search`, затем результат `Improve`;
- итоговое `Elapsed time`.

Остановка: `Ctrl+C`. Встроенного таймаута нет; для больших датасетов (80+80,
100+100) запуск может занять несколько минут.

## Формат датасетов

Файл: `{n}_{m}_{median}.txt`, 3 строки заголовка (пропускаются загрузчиком),
далее по одной записи на строку:

```
facility_index  client_index  cost  preference
```

Все 4 значения — числа (целые/дробные). Индексы 0-based, `facility_index`
индексирует строки матриц, `client_index` — столбцы. Записи заполняют
разреженно: не все пары (facility, client) присутствуют, незанятые ячейки
матриц `c` и `d` остаются нулевыми.

Пример (фрагмент):

```
0  3  480  10
1  7  910  12
...
```

Датасеты лежат в `datasets/`. Переключение — через правку пути в
`artifacts/import_from_file.py` (пока CLI нет).

## Переменные

| Имя | Смысл | Где задаётся |
|-----|-------|--------------|
| `V`   | порог (бюджет) задачи верхнего уровня | вверху `VND.py` / `VND_siplified.py` |
| `p`   | количество открываемых предприятий (медиана) | вверху `VND.py` |
| `n`   | мощность множества предприятий I | `artifacts/import_from_file.py` (жестко) |
| `m`   | мощность множества клиентов J | `artifacts/import_from_file.py` (жестко) |
| `c`   | матрица производственно-транспортных затрат (n×m) | `artifacts/import_from_file.py` |
| `d`   | матрица предпочтений клиентов (n×m) | `artifacts/import_from_file.py` |
| `y`   | бинарный вектор размещения (n,) — решение верхнего уровня | результат `Generate_y_start` / `Local_Search` |
| `x`   | матрица назначений клиентов (n×m) — решение нижнего уровня | результат `Folower` |
| `rho` | матрица радиусов пороговой устойчивости (n×m) | результат `Leader` |

Важно: `n` и `m` в `artifacts/import_from_file.py` прописаны вручную (`n = 20`,
`m = 20`) и не читаются из файла. При смене датасета меняются оба числа
и путь к `.txt`.

## Как переключать датасеты и параметры

Пока CLI нет — вручную:

1. В `artifacts/import_from_file.py`: поменять путь к `.txt` и значения `n`, `m`.
2. В `VND.py` (или `VND_siplified.py`): поменять `V` и `p` под датасет.
3. Запустить: `python VND.py`.

Значения `V` и `p` привязаны к конкретному датасету: `V = 39337`, `p = 15`
для `20_20_15.txt`, `V = 47000`, `p = 15` для `VND.py` (реальный набор).
Малый учебный пример (n=5, m=3, p=2) закомментирован в начале `VND.py` и
описан в `AGENTS.md`.

## Описание алгоритма

### Постановка задачи (bilevel)

Задача размещения предприятий двухуровневая:

- **Верхний уровень (Leader)** выбирает, какие предприятия открыть —
  бинарный вектор `y` с ровно `p` единиц. Цель — максимизировать радиус
  пороговой устойчивости `rho` при ограничении бюджета `V` на
  производственно-транспортные затраты.
- **Нижний уровень (Folower)** при заданном `y` распределяет каждого
  клиента по открытому предприятию с минимальным «расстоянием» из матрицы
  предпочтений `d` — матрица `x`.

Иерархия: `y` выбирается с учётом того, что `x` будет решён Folower'ом.
Целевая функция верхнего уровня: `V - f`, где `f = sum(c[i][j] * x[i][j])`
— суммарные затраты; радиусы `rho` вычисляются через `(V - f)` и (в
`VND.py`) нормализуются на число назначений `C`.

### Пайплайн решения

```
Generate_y_start(n, p)
        │
        ▼
    y (стартовое размещение)
        │
        ▼
┌───────────────────────────────┐
│  Local_Search(y)              │◄── цикл до локального оптимума
│    N(y) = лучший 1-swap       │
│    если улучшение, y ← N(y)   │
│    иначе стоп (k > 100 → stop)│
└───────────────────────────────┘
        │
        ▼
    r (локальный оптимум)
        │
        ▼
┌───────────────────────────────┐
│  Improve(r)                   │◄── просмотр окрестности 2-swap
│    ищет v с rho_new > rho     │
│    находит → возврат v        │
└───────────────────────────────┘
        │
        ▼
    s (улучшенное решение)
        │
        ▼
  s_rho > r_rho? ──да──► solve = s, повтор Local_Search
        │нет
        ▼
    остановка, печать Elapsed time
```

### Окрестности

- **1-swap** (`Swap(y)`): выбор одной единицы `i` и одного нуля `j`,
  `y[i] = 0`, `y[j] = 1`. Размер окрестности: `p * (n - p)`.
- **2-swap** (`Swap_2(y)`): выбор двух единиц `(i1, i2)` и двух нулей
  `(j1, j2)`, все четыре позиции инвертируются. Размер:
  `C(p, 2) * C(n - p, 2)`. Используется только в `Improve` после
  локального оптимума — «высший ранг» для выхода из мелкой ловушки.

### Local_Search

Последовательный просмотр 1-swap: на каждой итерации `N(y)` возвращает
первого соседа с улучшенным `rho` (greedy first-improvement) или сам `y`
если улучшений нет. Если `N(y) != y`, цикл продолжается, иначе `y` —
локальный оптимум. Ограничитель `k > 100` — защита от зацикливания;
при срабатывании печатается предупреждение, результат не гарантирован.

### Improve

После локального оптимума — единовременный просмотр 2-swap. Если найден
сосед с `rho_new > rho`, возвращается он, иначе `y` не меняется.
Внешний цикл в `VND.py` повторяет Local_Search + Improve, пока `Improve`
продолжает находить улучшение.

### Разница `VND.py` vs `VND_siplified.py`

Обе версии совпадают по пайплайну, различаются реализацией `Leader`:

- **`VND.py`**: `delta_rho = (V - f) / C`, где `C = sum(x)` — число
  назначений. Матрица `rho` строится как `x * delta_rho` (нормированный
  по клиенту радиус).
- **`VND_siplified.py`**: `rho` — матрица нулей, единственное ненулевое
  значение `V - f` ставится в позицию глобального минимума
  `c[i][j]` среди назначенных клиентов. Концентрация «радиуса» в одной
  точке (упрощённая аппроксимация).

Выбор версии — по задаче исследования: `VND.py` для основной модели,
`VND_siplified.py` как референс/вариант для сравнения.
